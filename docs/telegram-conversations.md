# 客服会话列表

后台 **Telegram 客服 → 客服会话**，复用 `telegram.php?view=conversations`。使用自托管 Vue 3 + Element Plus 表格、分页、标签、筛选和侧栏详情，不请求第三方 CDN，不需要数据库或新 Nginx 配置。

## 展示内容

- 用户昵称、当前已知 `@用户名`、Telegram 数字 ID。
- 最近消息、最近时间（北京时间）、消息条数及待回复 / 已回复 / 投递需核对状态。
- 按姓名、用户名、数字 ID、最近消息搜索；每页 20 个会话。
- 点击「查看会话」：按时间查看用户咨询与管理员人工回复，每页 50 条，第 1 页为最近记录。
- 文件 / 图片 / 语音等仅保存类型、文件名和附带说明，不下载附件、不保存 Telegram file_id，不把 Token 放进媒体 URL。

本版是查看列表，不是网页代发消息。人工回信继续在 Telegram 中回复对应卡片或用户消息。已发送表示 Telegram 已确认复制成功，不表示已读、已解决或卡密已激活；回复较早问题也会被统计为最近的一次人工回复。

## 从上线后开始记录

旧版只保存数字 ID 和投递状态，没有历史正文，因此不补抓旧对话。新功能只记录通过现有验证、屏蔽和限流规则的有效咨询及管理员人工回信；`/start`、欢迎卡片按钮、系统回执、活动领取卡密、群消息等不进入会话列表。用户主动发送的正文可能包含其个人信息，应避免发送敏感凭据。

`storage/telegram/conversations.json` 为独立私有文件，权限 0600，目录 0700；原 `state.json` 仍不保存聊天正文。历史写入共用 Telegram 排他锁，Webhook 更新编号 + 消息方向去重。先记录待发送，再记录实际复制状态；复制成功而管理员成功回执失败时，保留真实已发送状态。超时与进程中断不冒充发送成功。

默认启用后续记录，保留 30 天，最多最近 5000 条消息（先触及者生效）。后台可关闭后续记录或选择 7 / 30 / 90 天；关闭不影响正常客服收发，缩短期限立即清理超期记录。页面读取始终过滤过期内容；现有每分钟 `bin/telegram-tick.php` 负责磁盘过期清理，不新增计划任务。

历史绑定当前 Token + 管理员的单向摘要，更换绑定后不展示旧绑定记录，并在下次写入或定时清理时替换；新绑定默认开启 30 天。备份中的历史内容不会随在线过期清理自动删除，应按私有备份的保留规则管理，勿提交仓库或复制到公开目录。

列表 / 详情使用密码会话 + CSRF POST，仅返回该管理员的客服数据，不回传机器人凭据或完整 Telegram 请求对象。页面与接口 `Cache-Control: no-store`，不将查询正文放进 GET URL。Vue 以文本渲染所有用户字段，无 `v-html`、远程图片加载或运行时模板编译。

```sh
PHP_BINARY=php python3 tests/telegram-http.py
php tests/telegram-announcements.php
cd frontend && npm ci --ignore-scripts && npm run build
```

合成数据测试涵盖身份、双方正文、发送成功/失败/限流/超时、重复 Webhook、关闭记录、过期清理、容量限制、分页、绑定隔离、CSRF 与私有路由。本地浏览器已验证表格、用户名搜索和双方消息详情，不往正式库灌入演示对话。
