# 当前方案：每个游戏一个固定地址

2026-09-12 根据用户最终要求落地：**纯 PHP、服务器目录存包、JSON 存元数据、PHP 配置密码校验，无数据库。** 此文件取代此前 MySQL/任务队列等初稿建议。

## 固定绑定

- 三角洲国服安装器固定 app_key=mtx-dfm-cn，接口 `/api/update.php?app=mtx-dfm-cn`。
- 后续暗区等其他游戏新建独立 app_key 和接口，再重打对应安装器。
- 客户端不做游戏列表和地址输入框；后台可统一管理多个固定游戏。
- 固定的是版本接口，文件按内容摘要不可变保存，避免同名覆盖造成缓存/下载混乱。

## 当前服务端已经完成

密码登录、游戏配置、上传 TIPA、归档和身份检查、准备产物 TAR 回传、发布/下架/历史内容复制、签名版本接口、短期下载、断点续传、文件锁与审计。详细启动和部署见项目 README。

## 当前原安装器的实际情况

工程：`/Users/xxx/Documents/code/定制版巨魔/TrollInstallerX`。

- 原始 TIPA 在编译阶段转成 MTXPayload.tar。
- Installation.swift 从 Bundle 取归档，并检查编译期摘要。
- MTXHostInstaller.m 的载入器还检查固定 Bundle ID、源摘要、Main 和 MTXMenuIcons.ttf 文件清单。
- Helper/MTXInstallHelper.m 同样调用该载入器。
- 当前成功界面提示卸载安装器，长期保留行为需另行真机验证。

因此本轮**仅完成服务端**。原安装器尚未连接这个 API，也没有编译或生成远程版安装器。

## 下一步客户端接入

1. 每次构建固定 app_key、update_url、expected_bundle_id、profile_id、可信发布公钥和下载域集合。
2. 在安装前检查更新，验签后下载到独立缓存；校验真实长度与 SHA-256。
3. 将远程分支的编译期业务包摘要改成签名清单中的期望摘要；固定游戏身份和资源白名单继续保留。
4. 客户端与助手一起验证相同可信清单及不可变资源快照。
5. 安装成功才记录 installed_sequence。下载成功不是安装成功；卸载重装导致记录丢失时标为待确认。
6. 一份专用安装器在同游戏兼容结构内完成版本 A→B 的真机更新测试。

同一游戏的新版本若改变 Frameworks、资源、扩展或准备契约，仍须适配安装器。此服务端不执行源包，不自动签名业务程序、不触发 Xcode，也不承诺任意 TIPA 均适配现有安装流程。

## 上传体验

现有三角洲配置：上传 TIPA → 保存草稿 → 上传匹配的 MTXPayload.tar → 结构和摘要检查 → 管理员确认兼容测试 → 发布。

原始 TIPA 模式可供其他直接接收 TIPA 的客户端使用。选择此模式不会让现有 TAR 加载器自动接受原始 TIPA。

源包准备自动化可在后续接独立 Mac worker；本轮保持人工准备，以避免 PHP 后台伪报转换完成。
