# 当前方案：共用接口 + 游戏 ID

2026-09-12 按用户要求落地：纯 PHP、目录存包、JSON 元数据、密码登录，无数据库。

## 绑定方式

- 所有游戏共用 `/<随机入口>/api/update.php`；安装器附加 `game_id` 选择对应游戏。
- 后台新建游戏时自动分配递增数字 ID；现有三角洲为 1。内部 app_key 和产物契约自动生成，旧三角洲标识保留。
- 管理员选择 ID 导出对应公开配置并重打安装器，客户端没有游戏列表或地址输入框。同游戏换包不必重打。
- ID 与分配计数器持久化到 JSON，在文件锁内生成。停用不回收 ID；升级/备份保留原状态。
- 旧 `app=mtx-dfm-cn` 与票据 `app_key` 仍兼容，同时指定两种身份时检查一致性。

## 已实现的客户端流程

定制版巨魔远程版 0.8.2 / build 18：点击“安装” → 签名更新查询 → 真实 TIPA 字节进度下载 → 对应 TAR 下载 → 校验不可变资源快照 → 准备缓存 → 原有安装流程。下载/缓存错误显示重试，安装阶段异常才展示诊断；用户界面不展示更新说明或前置版本选择。最终系统 App 替换仍需确认。

主进程与助手使用 P-256 验签，核对 ID、Bundle ID、契约、时间、nonce、长度及摘要；序号缓存按游戏隔离。包名与 URL 不是可信身份依据。

## 发布方式

现有巨魔：上传 TIPA → 上传匹配的 MTXPayload.tar → 结构与摘要校验 → 兼容测试确认 → 发布。PHP 不运行上传程序或自动生成 TAR。原始 TIPA 模式仅用于支持该格式的其他客户端。

服务端支持密码会话、CSRF、限流、短期票据、HEAD/Range、发布/下架/历史复制、原子 JSON 和审计。随机入口配合 CDN/WAF 规则，入口本身不是认证凭证。

## 验证状态

本地 PHP、跨语言下载/校验和源码测试通过，iOS Release 构建成功；生产部署和真机安装尚待验证。没有发布真实业务包。同游戏若改变准备结构、资源或扩展，仍需适配安装器。
